Recap of the first week learning go

October 4, 2026

So I finished the first week of my Go + Backend Ultralearning Project and, to be completely honest, it was not smooth sailing. I’m starting off with Go and here is what I have learned.

Day 1#

A plan which sounds good in theory != Useful in practice#

So my original plan was to:

Step Focus What
1 Recall Anki reviews
2 Concepts Read the book materials
3 Procedures Work on a project
4 Facts Capture facts to Anki
5 Log Reflection and TLDR

This plan had a lot of flaws, which are not that obvious when you are planning. For example:

  • The concepts being read in the book don’t catch up with the concepts that are already being demanded by the projects.
  • Instead of focusing on things that are applicable right now ➡ Rigid structure which doesn’t adapt to the flow of progress.
  • Which facts were worth capturing and which were not?

I was still able to do a project already (it was a number guessing game), but it didn’t teach me a lot and was really simple.

Day 2-4#

So I reflected on Day 1 and decided to go with a new approach. I would use a resource called “Learn Go With Tests” a.k.a LGWT. It was a HUGE improvement compared to the approach of Day 1. So my schedule would look like:

  • Anki Flash Cards
  • LGWT ➡ Reading & typing code
    • Creating my own file where I would apply the concepts
    • The Feynman Technique
  • Summary of everything that was learned that day
  • Extraction for Anki
  • TLDR

I flew through the sections with confidence and at quite a high tempo, slowly building a good foundation and understanding of Go.

Day 5-6#

I talked so highly about the last pivot, right? I surely didn’t pivot again on Day 5, right? RIGHHHHT? Well, I did. I remembered the Ultralearning part of the project and what kind of standard of directness is demanded. I was honestly also getting bored of LGWT and wanted to start a project.

So I built on top of the foundation from Day 2-4 and I made a 2.0 version of the original plan:

  • Read about the topics in books that I learned the day before or what I struggled with
  • Work on a project
    • Every time I didn’t know something ➡ I would write it down as a Todo in the code comments
    • I would read documentation, blogs, and books
    • I would also create a temporary file where I would isolate one thing at a time
    • I would do the reading and practicing in isolation until I understood it, then go back to the main project and use what I had learned
  • Extract important facts and concepts to Anki
  • Plan tomorrow’s reading and focus
  • Make a TLDR and evaluation of the day

What was so special about this approach?#

Well, even though I would still have the same “problem” of diving into projects that I didn’t have the knowledge for, this time I would systematically work on those gaps for the sake of the project. If I had continued with the 2nd approach, I would have laid a better foundation, but it would just all fluff up in my brain and when would I know which time was right to start with projects?

I think this is a really good mix of both worlds and what actually led me to finishing my 2nd project.

CLI Task Manager Tool#

I basically built a CLI tool which manages tasks from the terminal. You can add, delete, mark, and list tasks, and it is all saved and handled within a JSON file.

It taught me a lot about File I/O, JSON handling, and modular code architecture, especially about Go’s modules and packages.

If you are more interested in the project, I showcased it in my YT video and you can also click here for the GitHub repo ;)
